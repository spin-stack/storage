# Production comments that describe a withdrawn mechanism as if it were still here. Each
# one is a lie a reader is told to trust, and each one is owed a correction.
#
# Read hack/comment-rot.sh first, then hack/comment-rot-allow.txt. The difference between
# that file and this one is the whole design: there, a comment names a withdrawn mechanism
# **to say it is gone**, and it is correct for ever; here, a comment names it in the
# present tense — a contract, an operator's remedy, a description of what a function does —
# and a reader believes it. CLAUDE.md says the decision lives in the code at the line that
# makes it. These are the lines where that stopped being true.
#
# THE RATCHET TURNS ONE WAY, and hack/comment-rot.sh enforces both directions:
#
#   - a finding in neither list fails the gate, so the set cannot grow. A new comment that
#     describes the upload chain, the checkpoint or the lease gate as current costs a
#     deliberate line here, with an owner, in the commit that writes it.
#   - a line here that no longer matches a finding fails the gate too, so an entry cannot
#     outlive the comment it names. Fixing a comment means deleting its line, in the same
#     commit. hack/deadcode-pending.txt carries the same cross-lane rule: this file is not
#     one lane's private property while it is shrinking.
#
# A pinned COUNT was rejected for the reason this repository has paid for twice: a number
# can be satisfied by fixing one comment and writing another, with nobody seeing the swap.
#
# WHY THIS LIST LANDS FULL RATHER THAN EMPTY. Fixing these means editing twenty-five files
# across every lane in the tree, and a gate that is red on the day it lands is a gate
# somebody deletes — which is written down in the Taskfile as the reason `deadcode` stayed
# out of every gate for two waves. So the debt is measured, pinned and printed on every
# green run, and it can only shrink.
#
# Format: `<file>:<symbol>:<term>  # what the comment claims, and what the code does`.
