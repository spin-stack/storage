# Production comments that name a withdrawn mechanism and are right to, each with the
# reason.
#
# Read hack/comment-rot.sh first: it explains what a finding is (one vocabulary term
# inside one declaration's comments), why the key is a symbol and not a line number, and
# why `nvme_remote_backlog_bytes` is not a mention of `remote`.
#
# Format: `<file>:<symbol>:<term>  # why`. The reason is not decoration — `task
# comment:rot` fails on an entry that has none, and fails on an entry that no longer
# matches a finding, so an allowlist cannot outlive the comments it excuses.
#
# WHAT BELONGS HERE. A mention that cannot mislead a reader about what the code does
# today. Three shapes, and between them they are most of this file:
#
#   1. the comment names the mechanism **to say it is gone** — "it went with the
#      uploader", "both went with the remote durability chain". These are the comments
#      this whole check exists to protect: they are why a reader stops looking.
#   2. the word is somebody else's mechanism — Go's garbage collector, a database
#      checkpointing its own pages inside the guest.
#   3. the sentence quotes a rule the code still enforces and names the withdrawn
#      component as the hazard the rule is for, rather than as something that runs.
#      INV-14's "a GC mistake costs a restore, not the data" is the whole of shape 3.
#
# WHAT DOES NOT BELONG HERE: a comment that describes the mechanism in the present tense.
# That is a lie about a system nobody has, it goes in hack/comment-rot-pending.txt with an
# owner, and the split is what keeps this file meaning something.

# removed the thing it names, which is the practice CLAUDE.md asks for.

# worth one line: their *files* were deleted. The local block engine — the write-ahead log,
# the virtio device, the interval map, the chunked image and the volume manager over them —

# --- somebody else's mechanism, spelled the same --------------------------------------
# The reason this check matches whole words rather than substrings, and the reason it can
# never be only a word list.
internal/lease/lease.go:package:gc                         # Go's garbage collector: a GC pause is one of the three slow round trips that make anchoring to the response unsafe

# --- a live rule that names the withdrawn component as its hazard ---------------------
# INV-14 is enforced by this interface today: Delete is reversible, Restore exists on both
# implementations, and NewS3Store refuses a bucket where a mark could not be undone. The
# sweeper the rule protects against does not exist, and naming it as the hazard is not the
# same as claiming it runs — the entries in the pending list next door are the ones that
# claim it runs.
internal/simio/objectstore/objectstore.go:Store.Restore:gc # quotes INV-14 ("a GC mistake costs a restore, not the data") as the argument Restore's place in the interface rests on
internal/simio/real/objectstore.go:ObjectStore.Restore:gc  # the operator step behind 'un-GC this' (INV-14) — the operator action, which exists and is tested
internal/simio/real/s3.go:ErrBucketNotVersioned:gc         # quotes INV-14 to say what is false on an unversioned bucket. The sentinel is returned by a live check
internal/simio/real/s3.go:NewS3Store:gc                    # "refuses a bucket the GC could not undo a delete on" — a property of the bucket, in the constructor that enforces it
internal/simio/real/s3.go:S3Store.Delete:gc                # "the object stays recoverable and the GC cannot destroy data" — the guarantee this Delete provides, whoever ends up calling it
internal/simio/real/s3.go:S3Store.Restore:gc               # quotes INV-14 ("a GC mistake costs a restore, not the data") as the argument this method's place on the production path rests on. The sweep that used to be named as the placer of the marker was corrected to Delete on 2026-08-11; what is left is the rule, and Restore is the half of it that runs
